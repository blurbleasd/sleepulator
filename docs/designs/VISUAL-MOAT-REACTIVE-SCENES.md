# CEO Plan: Visual Moat — Reactive Depth-Real Bedside Scenes
Generated by /plan-ceo-review on 2026-07-05
Branch: feat/reactive-scenes-audio-controls | Mode: SCOPE EXPANSION
Repo: blurbleasd/sleepulator

## Thesis (the strategic bet)

SLEEPULATOR's differentiator is not "another sound app." It is that **the screen itself
becomes the thing you want to look at while falling asleep** — a depth-real bedside window
whose scene *and* sound breathe with the night — backed by real audio engineering, OLED/
battery-respecting, no subscription, no account, no data leaving the phone.

The market splits into audio-first reactive AI (Endel — adaptive audio, throwaway visuals)
and content-library subscriptions (Calm, BetterSleep). The one kindred spirit on ethos is
Dark Noise (native, iOS-only, one-time purchase, craft) — but it's audio-only. On the visual
side, everything shipping is low-craft (Sleepwave wavescapes, Mesmerize patterns, orbs).
**Nobody renders GPU-real, depth-you-fall-into scenes that react to the sleep timeline.**
Endel made the *audio* react to time; nobody made the *visual scene* react.

**The honest starting point (corrected after reading the branch):** the reactive move is not
un-built — it is un-*proven*. The `sleepTimer.nightProgress` seam already exists on
`SceneContext` (`AmbientScene.swift:20`) and is already consumed live by `NightDarken`
(`:85`), `NightFade` dimming (`:103`), and inside several scene redraws
(the shipping `RainGlassView:110`, `DeepSpaceMetalView`, Aurora, StillWater, Embers).
(`NightDamping` is a separate orb-breath multiplier in `Theme.swift:26`, not the `:103`
dimmer — don't conflate them.) `SceneClock`
(`ShaderBackdrop.swift:21`) is a *separate* thing — the phase/elapsed integrator that keeps
motion continuous across freeze; it does **not** carry reactivity. So this plan is mostly
**finish + verify + extend**, not greenfield. The moat is real; it is 100% unverified on the
one device that matters. That gap is the whole point of the plan.

## Vision

### 10x Check
Not a better sleep app — a different category of object. Prop the phone at 11pm: rain beads
on glass, each drop an inverted lens of the city lights beyond, everything past the pane soft
with distance. As the sleep timer winds down, the rain thins, the glass fogs, the far lights
defocus, the scene slows and dims toward a single black frame — audio fading in lockstep. You
set none of it. The night did.

### Platonic Ideal
A small, deep catalog where the scenes that matter are rendered with real depth (near sharp,
far soft, foreground refracting background), each reactive to the sleep timeline, each
settling to OLED-black static when the room goes dark. No subscription, no account, no data
off-device. The only feature is *it's worth looking at*; the only proof is *you keep looking
at it, on the actual glass, at the actual bedside*. (Note: the registry already holds ~16
scenes — the deficit is not scene *count*, it's that almost none carry the depth grammar and
none are device-verified. This plan deepens, it does not add breadth.)

## P1 — GATE: On-device verification (blocks every item below)

**This is not a peer bullet; it is the gate.** No P2–P6a item counts as "done" until its
device pass is logged. The plan's own closing risk — "the rest of the scope is worthless until
this is honored" — makes P1 a precondition, so it is stated first and as a gate.

- **It is execute-and-log, not author.** `TESTING.md` already contains `### D. Night Limiter`
  (`:88`) and `### H. Ambient scenes — settle, freeze, phase clock` (`:108`). The deliverable
  is running those checklists on a real iPhone, installed, screen locked, over a full timer
  run, and recording each pass in the TESTING.md device-pass log — not writing new checklists.
- **Quantified budget (was asserted, never numbered):** overnight OLED/battery bar — define and
  record against a target: **≤ X% battery drain over an 8-hour locked run** and **no sustained
  thermal state above `.fair`** during a 30–60 min running-scene A/B. Pick X on the first run
  (measure the current shipping rain as the baseline, then hold new scenes to ≤ baseline).
- **Per-scene acceptance bar:** (1) the depth cue reads (refraction looks like a lens, not a
  dot; far layer reads soft/distant); (2) settles to a static dark frame when `paused`/idle
  (redraw loop *stopped*, verified — not a `settle=1` uniform); (3) running-state power within
  budget above.
- **"Clear win" A/B rule (P3):** rain-depth retires the old rain only if it holds framerate
  with no measurable battery regression vs the baseline **and** is preferred blind in ≥2 of 3
  bedside sessions. Otherwise iterate or cut.
- **Kill criteria for the bet:** if after two device-A/B cycles the depth rain can't clear the
  power budget without cutting drop count / fps / DoF taps below the point where the "whoa"
  survives, the depth-shader direction is cut back to the shipped 2D rain and the reactive work
  proceeds on the cheaper scenes only. Say it out loud now so it's a decision, not a drift.

## 0E implementation decisions (resolved this session)
- **P4 target:** upgrade **StillWaterMetalView (ocean)** to the depth grammar — highest reuse,
  closest analogue to rain-on-glass depth.
- **P2 contract:** **one shared "depth reactivity" vocabulary** — a documented mapping from
  `nightProgress` (0→1) to each depth knob (rain/particle density, fog opacity, bokeh blur
  radius, motion rate) that every scene interprets, so scene #3/#4 inherit reactivity for free.
  Name the target param + curve per effect; where a knob doesn't exist yet (glass-fog,
  bokeh-defocus), that's the new shader work, not a wish.
- **P3 A/B switch (reconciled with the branch):** the 0E "minimal DEBUG toggle" turned out to
  be **redundant** — `RainOnGlassDepthScene` is already DEBUG-registered (`:306`) and
  `HomeView.cycleScene` swipe-cycles every registered scene, so on a DEBUG build the A/B is
  already a left-swipe away. The real gap is release-build reachability (F4), not a debug
  toggle. So P3's mechanism = swipe-cycling on DEBUG + the F4 minimal release selector for
  TestFlight. No throwaway toggle gets built.

## Deep-review findings (resolved this session)
The 11-section review surfaced four still-open items; all decided:
- **F1 (arch/test):** the shared reactivity vocabulary lives in a **pure, unit-tested function**
  (`nightProgress` + scene params → density/fog/bokeh/motion), the `AudioMath` precedent. Buys
  off-device unit coverage of the reactivity curves — the one thing the device ritual can't give.
- **F2 (CRITICAL GAP, error):** on Metal shader load/compile failure, each depth scene **falls
  back to its 2D scaffold render + logs** (no silent black backdrop). `RainGlassView` already is
  the scaffold. Honors the "zero silent failures" prime directive.
- **F3 (observability):** **instrument the existing overnight diag log** (`9e76cd0`) with
  per-scene frame timing + `ProcessInfo.thermalState` + battery-level samples, so P3's "clear
  win" A/B is data-backed, not eyeball-only.
- **F4 (deploy/design, load-bearing):** **un-defer a minimal, release-capable scene switch**
  (a subset of P6b) so P3's A/B and P4's ocean are reachable on a TestFlight build at the
  bedside. The full live-preview picker stays deferred.

## Feasibility notes (verified against the repo)
- **`.layerEffect` single-layer constraint holds** — `RainGlassDepthView.swift:13,70` already
  applies `RainGlass.metal` to a `drawingGroup()`-flattened, pre-composited far world. The
  "bake the background to one sampleable layer" approach is already the shipped shape.
- **DoF/fog is the real new risk.** Bokeh-defocus + glass-fog must not become a per-frame
  multi-tap blur or a second sampled layer — RAIN-ON-GLASS-DEPTH-SPEC §6.2 already names that
  as the battery trap. Bake blur once into the composited layer; keep the shader's per-pixel
  work bounded. This is where P2's power budget gets spent — measure it (P1).
- **License resolved** — the "Heartfelt" CC BY-NC-SA port was rewritten as an original lens
  (`SPEC-STATUS.md:21`, MEMORY.md). P3 shipping the lens is legally clear.
- **Effort is device-pass-cycle-bound, not session-bound.** Because the scaffolding exists, the
  cost of P2–P5 is dominated by overnight A/B iteration on real hardware, not CC session count.

## Eng review — architecture decision (2026-07-05)

**Finding #1 (P1): build a shared `.layerEffect` depth-host before P2/P3/P4.** The `.colorEffect`
scenes ride `ShaderBackdrop` (SceneClock + `sleepTimer.nightProgress` + built-in `paused:` freeze).
`RainGlassDepthView` rides none of it: it freezes with `t: 0` (`RainGlassDepthView.swift:44`) — the
exact "snap back to birth pose" bug `SceneClock` was built to fix (`ShaderBackdrop.swift:16`), live
today in the DEBUG scene — uses an `if/else` branch swap instead of `TimelineView(paused:)` (resets
view identity on freeze), and takes no `sleepTimer` (so P2 reactivity has nothing to attach to). P4's
ocean is a **second** `.layerEffect`-depth scene with identical needs, which fires the rain-depth
spec's §5 "build the depth toolkit when the 2nd scene asks" trigger.

**Decision:** build a shared `.layerEffect` depth-host (mirror of `ShaderBackdrop` for lens scenes,
carrying `SceneClock` + `sleepTimer.nightProgress` + the `paused:` freeze, over a composited
far-world view). Rain-depth and ocean both ride it. This is "make the change easy, then make the easy
change" — the host lands first, then P2/P3/P4 become small. It also fixes the freeze-snap bug and
gives P2 its reactive seam for free.

**Sequencing impact:** P2/P3/P4 are now preceded by **T-host** (build the shared depth-host). P4's
"rework StillWater to the depth grammar" also means moving StillWater off the `.colorEffect`
`ShaderBackdrop` rail onto the new host.

**Test (REGRESSION) — already covered (correction).** The eng review flagged `SceneClock.tick` as
untested; that was a false positive (asserted from the Views code without checking the test target).
`AudioMathTests.swift:79 SceneClockTests` already covers every invariant the depth-host depends on:
monotonic `phase` for any `rate ≥ 0` (`testPhaseNeverRewindsWhenRateDrops:90`), `dt` clamp at `maxStep`
/ freeze-holds-pose (`testResumeGapIsClampedToFreezeInPlace:107`), and rate ≤ 0 clamp
(`testZeroAndNegativeRateHoldPhaseButAdvanceElapsed:128`). All 6 pass against the E1 changes. No new
test added (would duplicate).

**E1 / F1 / P2 status (built + unit-verified; on-device behavior unverified — P1 gate):**
- **E1** — shared `.layerEffect` depth-host `DepthBackdrop` (`ShaderBackdrop.swift`); `RainGlassDepthView`
  is a thin wrapper (dropped its own `TiltSource`/`TimelineView`/`t:0` freeze); `RainOnGlassDepthScene`
  passes `sleepTimer` + `tilt`, `usesMotion: true`. Committed `5cf29cf`.
- **F1** — `DepthReactivity` (`Services/DepthReactivity.swift`): pure `nightProgress → density/fog/defocus`
  vocabulary, smoothstep-eased, clamped, monotonic. 5 unit tests (`DepthReactivityTests`).
- **P2** — reactive-depth wired: `nightSlowdown: 0.5` (rain eases to half speed via the SceneClock
  rate); `RainGlass.metal` gains `fogAmt` + `defocus` uniforms (dry glass fogs, far world defocuses —
  the same 5 blur taps spread wider, no new per-frame cost); `RainGlassDepthView.makeShader` maps night
  through F1. Mist thins via the existing `density` uniform.
- **P4** — ocean on the new host: `StillWaterDepthView` + `StillWaterLens.metal` (new), registered as
  a DEBUG A/B sibling `StillWaterDepthScene` alongside the flat still water. The near swell refracts a
  composited sky far world (gradient + moon glow + hazy horizon) into a wave-distorted reflection —
  near-sharp swell, far-soft horizon — reactive via the same `DepthReactivity` (F1) + `nightSlowdown`.
  Second consumer of `DepthBackdrop`, proving the recipe generalizes (the spec §5 toolkit trigger). A
  `refraction` A/B knob (0 = flat mirror, proves the seam) mirrors rain-depth.
- **F2** — silent-failure guard: `Services/MetalShaders.swift` preflights the compiled metallib at
  launch (logs any missing known shader via a new `Log.scene` category) and `DepthBackdrop` gates its
  `.layerEffect` on availability — a missing lens renders the bare far-world scaffold, not a broken
  effect or silent black pane. **Fail-safe by construction:** if the library enumerates none of the
  known stitchable functions (enumeration gap), every shader is treated available so a working effect
  is never gated off; the pure decision `MetalShaders.isAvailable` is unit-tested (3 cases). Whether
  the gate actively falls back or is effectively log-only depends on runtime `functionNames`
  enumeration — verified on device — but it can only ever help, never break the working path.
- **F3** — measured A/B: `Services/SceneDiagnostics.swift` samples per-scene **fps + `thermalState` +
  battery** into the `Log.scene` overnight trail every ~30s of actual rendering. Fed one `frame()` per
  rendered frame by both hosts (`ShaderBackdrop` + `DepthBackdrop`); tagged with the active scene id
  (set in `HomeView.reconcileMotion`). Plain class, `SceneClock`/`TiltSource` pattern (no `@Published`).
  Only samples while animating — a frozen scene renders no frames, so settled-state power (trivially
  fine) never bloats the log. Turns P3's "clear win" + P1's power budget from a vibe into numbers.
- **P6a** — app-level "Ambient motion" toggle (Settings ▸ Display, `@AppStorage("ambientMotion")`,
  default ON): OFF adds `!ambientMotion` as another reason in `HomeView.scenesFrozen`, so the backdrop
  holds a static frame (and CoreMotion stops via a `reconcileMotion` onChange). An explicit override on
  top of system Reduce Motion, which by convention only gates parallax (SCREENSAVER-LIBRARY-SPEC §5) —
  this is the home for the user who wants the scene itself still. Added to Backup/Restore keys.
- **Verified:** Debug sim build SUCCEEDED (Metal + Swift compile clean, incl. the new ocean shader);
  14/14 unit tests green (`DepthReactivityTests` 5, `MetalShadersTests` 3, `SceneClockTests` 6).
  **Unverified on device:** freeze-in-place, the reactive settle, the ocean reflection look, parallax,
  the F2 fallback path firing, and the P1 power budget — shader constants + curve values are device-A/B.

## Open strategic risk (carried into the deep review)

device. The moat is real but unproven, and unit tests cannot catch the bugs that matter (no
real render thread / audio session in XCTest). P1 is the gate that converts that risk into a
repeatable ritual; every other item is worthless until P1 is honored.
